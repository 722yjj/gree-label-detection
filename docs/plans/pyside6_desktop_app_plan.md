# PySide6 桌面端开发方案

## 1. 背景与目标

当前项目的检测核心已经成型，稳定入口为：

- `label_detection.workflows.unified.run_unified_detection(template_input_path, target_image_path, output_dir)`

下一阶段不再改造检测主流程，而是在外围增加桌面端业务层，完成以下能力：

1. 接收扫码器输入的条码/编码。
2. 从模板库中查找并选定模板文件。
3. 接入相机或本地图片，获得待检测图像。
4. 调用现有检测核心，展示结果与过程状态。
5. 保存历史记录，便于复查和复跑。

本阶段优先保证架构清晰、主线稳定、便于后续接真硬件，不追求一次做完全部功能。

## 2. 约束与原则

- 不直接改现有检测主流程的业务逻辑。
- 新功能通过独立目录接入，减少对现有 CLI 和脚本的影响。
- `main` 分支保持稳定，只在功能分支开发。
- 第一版先支持 mock 扫码和 mock 相机，不依赖真实硬件。
- 第一版优先本地桌面场景，不做 Web 化。

## 3. Git 策略

### 分支规则

- `main`
  - 只保留稳定版本。
  - 不直接开发桌面端功能。
- `feature/pyside6-desktop-app`
  - 当前桌面端开发分支。
- `backup/...`
  - 仅用于封存清理前的本地状态，不参与正式开发。

### 建议提交流程

每做完一个清晰的子功能就提交一次，避免把 UI、数据库、设备接入混在一个 commit 中。

推荐提交粒度：

1. `docs`: 方案文档、开发说明。
2. `scaffold`: 目录骨架、入口、基础窗口。
3. `repo`: 模板库与数据访问层。
4. `ui`: 主界面交互。
5. `worker`: 检测后台线程。
6. `camera`: mock/真实相机适配。
7. `scanner`: mock/真实扫码输入适配。

## 4. 总体架构

```text
扫码器/键盘输入
  -> 编码解析
  -> 模板库查询
  -> 模板选择
  -> 相机采图 / 本地图片导入
  -> 调用 run_unified_detection
  -> 结果展示 / 历史记录保存
```

架构分层：

- `desktop_app/ui`
  - 负责窗口、控件、信号连接、页面展示。
- `desktop_app/controllers`
  - 负责页面动作编排，串联 UI、模板库、检测服务、相机。
- `desktop_app/repositories`
  - 负责模板库和后续历史记录数据访问。
- `desktop_app/services`
  - 对接现有检测核心，封装结果输出路径和运行调用。
- `desktop_app/workers`
  - 负责后台线程，避免阻塞界面。
- `desktop_app/devices`
  - 负责扫码器和相机适配层，后续可扩展真实硬件实现。

## 6. 第一版界面范围

主窗口拆成五块：

1. 编码输入区
   - 手动输入编码
   - 模拟扫码按钮
   - 查询模板按钮

2. 模板信息区
   - 当前编码
   - 匹配到的模板列表
   - 默认模板/当前模板路径

3. 图像输入区
   - 选择本地图片
   - mock 相机取图
   - 图像预览

4. 检测结果区
   - 运行状态
   - 综合判定
   - 输出目录
   - 关键字段摘要

5. 历史记录区
   - 最近运行记录
   - 预留后续“重新打开结果目录”能力

## 7. 模板库设计

第一版不引入服务端数据库，使用 `SQLite + 文件系统`。

数据库建议表结构：

### `templates`

- `id`
- `code`
- `variant`
- `display_name`
- `source_type`
- `source_path`
- `preview_path`
- `label_kind`
- `is_default`
- `created_at`
- `updated_at`

说明：

- `code` 是主编码，例如 `600004075219`
- `variant` 是变体，例如 `01`
- `source_type` 支持 `pdf` / `image`
- `source_path` 指向真实模板文件
- 同一 `code` 允许多条记录，其中一条可设为默认模板

### 模板库初始化策略

第一版先不做复杂导入界面。

直接从现有样本目录扫描生成初始数据：

- `samples/pdfs`
- 后续可扩展 `samples/images/original`

编码与变体规则沿用现有批量样本逻辑：

- 主编码取文件名中的主数字串
- `-01`、`_1` 等后缀视为同一编码的不同变体

## 8. 扫码器方案

### 第一阶段

- 不接真实扫码枪。
- 直接使用输入框模拟扫码。
- 回车视作“扫码完成”。

### 第二阶段

- 接入 USB HID 键盘模式扫码枪。
- 在 UI 上将焦点保持在编码输入框。
- 扫码完成后自动触发模板查询。

### 第三阶段

- 如有需要，再增加 CDC/HID-POS 等更强控制方式。

## 9. 相机方案

### 第一阶段

- 不接真实相机。
- 直接选择本地图片，模拟拍照输入。

### 第二阶段

- 增加 `OpenCV VideoCapture` 相机适配。
- 先兼容普通 UVC USB 相机。

### 第三阶段

- 如后续使用工业相机，再新增专用 adapter。
- 工业相机适配不应影响控制层和 UI 逻辑。

## 10. 检测调用方式

桌面端不直接重写检测逻辑，只通过服务层调用：

- 输入：模板路径、目标图片路径、输出目录
- 输出：检测结果字典 + 结果目录

服务层职责：

1. 规范输出目录命名。
2. 调用 `run_unified_detection(...)`
3. 读取结果摘要。
4. 以适合 UI 的结构返回。

## 11. 线程模型

界面线程不直接跑 OCR/VLM 检测。

采用后台线程执行检测任务：

- 主线程：界面交互、展示结果、启停任务
- 工作线程：执行检测服务

线程要求：

- 启动时禁用“开始检测”按钮
- 完成时恢复按钮状态
- 失败时把异常转成 UI 可读提示

## 12. 开发阶段拆分

### Phase 1: 基础脚手架

目标：

- 建立 `desktop_app` 目录
- 建立主窗口
- 跑通 mock 编码输入
- 跑通本地图片选择

交付：

- 可以启动桌面程序
- 可以显示窗口和基础控件

### Phase 2: 模板库与查询

目标：

- 新增模板仓储层
- 支持根据编码查找模板列表
- 在界面中展示查询结果

交付：

- 输入编码后可看到模板候选

### Phase 3: 检测任务接入

目标：

- 新增检测服务层
- 新增后台 worker
- 在 UI 中触发现有检测核心

交付：

- 选定模板和目标图后可以运行检测
- 界面可以显示综合判定和输出目录

### Phase 4: mock 设备抽象

目标：

- 把“输入框扫码”和“本地图片导入”收敛进设备抽象层
- 为真实扫码枪和相机预留接口

交付：

- UI 不再直接依赖底层输入实现

### Phase 5: 真设备接入

目标：

- 扫码枪接入
- UVC 相机接入

交付：

- 基本工位流程可用

## 13. 第一版不做的事

- 不做多窗口复杂流程。
- 不做远程服务端部署。
- 不做账号权限系统。
- 不做完整模板维护后台。
- 不做工业相机专用 SDK 接入。
- 不做复杂历史报表系统。

## 14. 当前落地顺序

本次代码改动先做到：

1. 建立文档与目录骨架
2. 建立桌面程序入口
3. 建立主窗口基础布局
4. 建立模板仓储、检测服务、后台 worker 的基础接口
5. 先接 mock 输入，不接真实硬件

## 15. 运行建议

当前阶段推荐本地静态验证与基础启动验证，不做完整端到端硬件联调。

后续在服务器或正式环境拉取后，可按功能分阶段运行。
